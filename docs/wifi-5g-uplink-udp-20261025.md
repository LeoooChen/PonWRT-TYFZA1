# 5 GHz 本机 UDP 上行丢包定位与修复

## 确定的丢弃点

在固定位置、信道149/HE80/30 dBm、1200字节UDP载荷、10 Mbps上行测试中，
向本机 iperf3 发送的数据包已经完整到达 IPv4 LOCAL_IN，随后在 UDP socket
接收队列因容量不足而丢弃。

最直接的一轮：发送12,501包，独立只读 netfilter 探针看到12,501包；接收端
得到11,885个载荷包，`Udp.RcvbufErrors`和`Udp.InErrors`均增加616，与iperf3
报告的616包丢失完全一致。UDP校验错误与MemErrors计数没有增加。
原先DIG验证的两轮5G丢包598+462=1060，也与本轮开始时的全局溢出计数1060吻合；
后续实测建立了逐轮的前后计数证据，不只依赖这个历史累计值。

内核 socket 实际上限为212,992字节。1200字节载荷对应的接收skb占用1,920字节，
只能容纳110包。回切复现时排队内存峰值211,200字节，紧贴该上限。普通流量复现中，
探针记录到135.495 ms的到包间隔和单个1 ms窗口内73包的集中到达；这些包最终都
到达UDP入口，不能将接收应用的缺包数直接归为射频或PE丢包。没有进一步断言该间隔
来自客户端节能、空口调度或某一个内核调度环节。

## 修复

新增板级 `/etc/sysctl.d/30-tyfza1-udp.conf`，把
`net.core.rmem_default`设为524,288字节（512 KiB），足以容纳本轮256包、
每包1,920字节的实测突发。实际socket上限同步变为524,288，队列实测峰值489,600；
修改的是内核可用的接收容量。接收内存按需占用，不预先为每个socket分配512 KiB。

OpenWrt原有sysctl服务在启动时读取该目录，再读取用户 `/etc/sysctl.conf`。
应用自行设置的SO_RCVBUF和既有socket沿用其原有值；配置作用于之后新建的socket。
本轮rmem_max保持4 MiB，RPS最终恢复原配置0。无线驱动、射频参数与PE准入策略均未修改。

这项修复针对本机UDP应用接收队列溢出；不据此宣称解决其他空口或硬件转发丢包。

## 排查中没有采用的改动

- 已用内核A-MSDU函数构造1至8子帧，确实能看到最后一个子帧保留较大聚合缓冲。
  但本轮实际UDP流的所有接收skb均为1,920字节，不支持把该合成现象当作这次丢包根因，
  没有修改cfg80211拆包算法。
- ARM/PE路径会自动切换；单次观察RXQ_owner=ARM不能代表整轮都走ARM。对照记录保留
  实际所有权和探针计数，没有增加强制慢路径的生产开关。
- RPS=8可减轻部分突发丢包，但未彻底消除，最终恢复0，没有把接收CPU调整作为修复。

## RAM 对照与边界

保持信道、带宽、功率、目标10 Mbps、1200字节载荷及RPS=0。256包突发通过
iperf3的 `-b 10M/256` 产生；每轮12秒。正常流量使用 `-b 10M`，没有指定 `-w`。

| 对照 | socket默认上限 | 发送包 | 实收载荷包 | 实际缺包 | UDP溢出增量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通5G流量复现 | 212992 | 12501 | 11885 | 616 | 616 |
| 256包突发，基线 | 212992 | 12544 | 9098 | 3446 | 3446 |
| 256包突发，复测 | 212992 | 12544 | 9746 | 2798 | 2798 |
| RAM改512 KiB | 524288 | 12544 | 12544 | 0 | 0 |
| 回切212992 | 212992 | 12544 | 7584 | 4960 | 4960 |
| 再改512 KiB | 524288 | 12544 | 12544 | 0 | 0 |
| 去掉探针，512 KiB | 524288 | 12544 | 12544 | 0 | 0 |
| 去掉探针，回切212992 | 212992 | 12544 | 7215 | 5329 | 5329 |
| 去掉探针，再改512 KiB | 524288 | 12544 | 12544 | 0 | 0 |

最后重载同一个生产无线RAM模块重新关联，首轮普通5G上行12,502包全部收到，
UDP溢出增量0。最后三轮不带探针的回切验证排除了观察模块改变结果的解释。

实际缺包按发送包数减接收载荷字节/1200计算。iperf3的序号丢包统计可能遗漏末尾
没有后续序号证明的丢包，例如最后回切轮报告5194，实际尾丢再加135，共5329，
恰好等于内核socket溢出。没有用较小的前端统计替代实际缺失。

验证时仅将仓库配置复制到 `/tmp/5g-uplink/`，用 `sysctl -p` 应用；配置文件的
启动加载路径已与OpenWrt sysctl服务核对。没有为这个两行配置编写重复其内容的单元测试，
也不把配置变更描述成无线驱动修复或新模块构建。

只读观察器源码为 `tools/live_udp_queue_observe.c`：在IPv4 LOCAL_IN处按目标端口
和1200字节载荷计数，记录真实skb内存与socket接收预算。观察器只用于定位，最终
验证和留机状态均已卸载。另一个A-MSDU合成测试模块也已卸载。


原始记录在 Mac `现场记录/20261025-5g-uplink/`，结构化结果和日志散列见
`manifests/wifi-5g-uplink-udp-20261025.json`。全部运行在RAM，未刷Flash。
