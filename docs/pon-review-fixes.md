# 2026-10-08 四项问题修复

四项均为真实问题，按当前移植代码、GPL参考和本机原厂反汇编核对后修复。

1. MPCP NACK：本机ca-ne.ko的aal_epon_mpcp_rx_reg_frame_handler在df240提取0x20d8的register_flag[23:16]；NACK=4后清除0x200c bit0。原生驱动改为该路径，0x2010 FIFO只统计可见注册帧。60秒静默只在新的注册报文事件触发，读取残留flag不会不断延后期限；到期后工作队列在PCS同步时重新启动注册。原厂只明确LLID0归属，当前多LLID配置将静默作用于共享注册引擎，状态输出silence_scope=shared-engine，未据此推断各LLID收到NACK。
2. OAM发现退回：对端Local不变但Remote缺失或不匹配时，重置当前会话、认证结果和扩展协商，增加Information revision并要求新回抄。历史成功/失败计数保留。持续EVAL报文不能继承accepted。
3. QM缓冲归还：持久化EQ4/EQ5各256项待归还队列。先退役EPP，再入队，成功PUSH后才移除地址。NAPI归还采用即时BID/FIFO就绪检查，忙时保留地址；原有1ms引擎定时器在队列非空时调度NAPI，即使没有新RX中断也能重试。两个EQ独立归还；停止时保留待归还资源，下次TQM复位后清除旧队列并重装全部缓冲。qm_state提供refill_pending/retries/returned/peak，归还等待不再冒充一次rx_dropped。
4. 完整构建：port/scripts/build.sh、scripts/build_lan_ui.sh及scripts/build_bringup_kernel.sh共用tools/prepare_pon_runtime.py。输入验证、SerDes转换、本机BOSA复制、原ONU MAC提取及私有配置安装全部在make前完成；缺失资料或空表直接失败。完整构建不再依赖旧工作区files/残留。
